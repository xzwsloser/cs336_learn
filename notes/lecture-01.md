## Tokenization

### 基础概念

Tokenizer: 完成文本和编码之间的相互转换

压缩比: 字节数量 / token 数量

### Tokenizer 构建

Tokenizer 可以使用如下几种方法构建:

1. 字符 -> UniCode 编码: 缺点是词表空间太大，优点是压缩比比较大
2. 字符 -> UTF-8 编码: 缺点是压缩比小，优点是词表空间比较小
3. 对于句子进行分词操作，例如 `我爱中国 -> 我/爱/中国`，然后对于分词中的每一个部分编码，但是缺点是词表可能是无界的

### BPE

核心思想: 使用原始文本构建分词器，找出语料库中一起出现次数最多的词对

算法流程:

1. 字节级 BPE 使用 UniCode 编码，英文使用一个字节、中文使用三个字节，后续操作都是对于字节对进行操作的，首先按照前后关系构建 token 对并且进行计数操作
2. 出现频率最高的相邻 token 对合并作为一个 token，并且加入到原来序列中
3. 持续上述操作，完成词表构建即可

分词器使用:

1. 遍历之前的合并规则集并且应用在新的字符串中，贪心匹配
2. 匹配分词

> 🤔 字节级 BPE 在分词的时候，将句子中的所有符号(包括中英文字体、标点符号等)拆分为 UTF-8 码点，例如英文对应一个字节、中文对应三个字节，然后对于这一串字节流进行分词操作；但是现代大模型在 BPE 之前还存在一个**预分词**的过程。
>
> 预分词处理句子得到块序列，例如 `"AI 世界"` -> `["AI", " ", "世界"]`，然后对于每一个块使用 BPE 算法，这样做使得跨块的向量符号永远不会被合并(例如中英文混杂、标点符号和字体混杂等)。
>
> 预分词 + BPE 推理过程:
> 1. 预分词 -> 得到块序列 `[块1, 块2, ...]`
> 2. 对于每一个块独立执行:
>    1. 块内容转换为字节/字符序列
>    2. 按照训练时候学习到的合并规则贪心合并
>    3. 重复直到没有合并的对
> 3. 每一块产生的 token 按照顺序拼接
